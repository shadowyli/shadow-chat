# 逐版本发布规则

影聊由 shadowyli 个人维护。版本信息、更新说明和附件以本仓库 Releases 为准，
镜像下载页面从已发布 Release 同步，不自行编写另一套软件版本记录。

每个版本包含：

- Windows 安装包及完整源码归档。
- 新增、改进、修复、适用系统、安装升级及数据保留说明。
- build-info.json：源码提交、构建环境、工具链、附件大小与摘要、测试结果及限制。
- SHA256SUMS.txt：源码、安装包和构建信息的校验清单。

测试版标签为 `v<版本>-test`，正式版为 `v<版本>`。不覆盖既有标签或发布资产。
说明文案可修订，修订不会改变历史安装包和源码归档的字节内容。

在独立工作目录冻结源码，完成源码审查、构建、相关回归、安装和覆盖升级验证。
提交并推送到工作分支；PR 合并和正式发布另行确认。源码归档必须来自对应提交。
发布后重新下载远程安装包并核对 SHA-256。

更新说明仅记录影聊客户端变化。下载站的页面、架构、权限和部署操作留在下载站项目。
构建信息中仍需准确记录真实运行库和许可证，不能因精简介绍而隐瞒依赖。

普通 `local`、`dev`、`main` 构建默认从本仓库 Releases 读取对应通道的版本，
“立即下载”直接打开所选 Release 的安装包附件地址，不跳转介绍页或 Release 页面。
只有显式传入 `--environment local --local-update-port <端口>` 的调试构建才使用本机更新服务；
原生合成资料预览继续通过该参数隔离，不将调试构建作为常规交付安装包。
测试与正式通道隔离，不能将本地测试包改名作为正式版分发。
版本服务失败不阻止启动、登录或收发；有更高版本时每天最多提示一次。
本机合成资料验证不等同于真实办公网络和全部 Windows 环境验收。

## 更新维护与交接

在 `shadowyli/shadow-chat` 创建新 Release，按通道使用 `v<版本>-test`
（prerelease）或 `v<版本>`（正式版），附上对应环境的
`ShadowChat-<版本>-<local|dev|main>-setup.exe`、版本说明及校验信息。
客户端会选择本通道、本环境中版本号最高的有效安装包，下载地址直接来自该附件。
不用启动维护者的电脑、本机网页或下载镜像站，也不在客户端保存发布凭据。
交接时给后续维护者仓库与 Release 发布权限，并保留构建脚本和版本归档。

已安装的旧版二进制不会因源码修改而自动改变更新逻辑，
首次迁移需要覆盖安装包含本修复的新版本；不得替换已经发布的旧版附件。
