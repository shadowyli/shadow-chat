# 影聊完整改造方案

## 1. 产品定位

影聊是一款无需账号、无需服务器、面向公司局域网的日常办公聊天工具。它不是另一个“大而全”的协作平台，而是把最高频的三件事做好：找到同事、发消息、发图片或文件。

产品承诺：

> 聊天、文件和通讯录始终留在局域网；除可关闭的版本检查外，不连接外部服务。

安全边界必须说清楚：影聊保证自身不提供公网中转、云上传、代理、远程插件或绕过公司网络策略的后门；它不宣称能够约束用户安装的其他软件。

## 2. 高频场景排序

1. 私聊和查看最近消息。
2. 一次拖入多张图片，一次确认、成组展示、逐张查看和保存原图。
3. 在通讯录里快速找到新同事并发起会话。
4. 群聊和全员群。
5. 发送普通文件。
6. 修改名字、头像和在线状态。
7. 换电脑时导出、导入工作区。
8. 低频高级设置、聊天存档和诊断。

桌面共享、语音、插件、广播消息、复杂字体和表情设置不进入主路径，默认关闭或收进“更多”。

## 3. 信息架构

主窗口采用稳定的三栏结构：

- 左侧导航：消息、通讯录、更多、我的。
- 中间列表：当前模块标题、统一搜索、最近会话或联系人列表。
- 右侧内容：会话标题、消息流、输入框和发送动作。

命名规则：

- “全部频道”改为“全员群”。
- 不再用“用户”作为用户可见的主入口，统一叫“通讯录”。
- “聊天”在导航里叫“消息”；只有具体多人会话叫“群聊”。
- “配置、VCard、存档”等技术词替换为“设置、个人资料、聊天记录”。

响应式规则：窗口宽度低于 900 px 时保留导航栏，只显示会话列表或当前会话；进入聊天后显示返回按钮。

## 4. 核心交互

### 4.1 最近消息

- 启动后默认进入最近消息。
- 会话项展示头像、姓名或群名、最近一条消息、时间和未读数。
- 点击即在右侧打开，不再弹出独立窗口。
- `Ctrl+K` 聚焦统一搜索，`Ctrl+1` 消息，`Ctrl+2` 通讯录，`Esc` 清空搜索或返回列表。

### 4.2 多图发送

- 拖入或选择两张及以上图片时，只弹出一次确认。
- 确认窗显示最多 8 张缩略图、总张数、总大小和可选说明。
- 同一批图片在消息流中合并为一个浅蓝或白色图片气泡，不产生五十条独立视觉消息。
- 首屏最多展示 9 张，更多图片显示 `+N 张图片`。
- 点击图片沿用原协议打开原图；文件仍逐个传输，保证与原 BeeBEEP 客户端兼容。
- 某张失败只标记该张并允许重试；后续版本增加“全部保存”。

### 4.3 长消息

- 正文超过 700 个字符时展示摘要和“展开全文”。
- 展开只改变本地视图，不修改聊天记录。
- 搜索、复制和导出仍基于完整原文。

### 4.4 通讯录

- 默认显示在线同事，离线同事折叠在后。
- 搜索同时匹配姓名、备注、部门和计算机名；IP 只作为诊断信息，不作为主身份。
- 新同事在局域网出现后自动进入通讯录，点击即可发起私聊。

## 5. 首次使用

首次启动只保留一个三步引导：

1. 设置显示名称和头像。
2. 确认当前局域网和“数据不出局域网”的说明。
3. 选择更新提醒：推荐“每 7 天仅检查一次版本号”，也可选择“完全离线”。

无需注册。用户身份应由工作区内的本地身份密钥和资料决定，IP 只负责发现与连接；换 IP 不应变成新用户。

## 6. 工作区备份与换机

采用单文件扩展名 `.beebeep-workspace`，交互上参考项目型软件：

- “导出工作区”包含个人资料、本地身份、联系人、群聊、设置和聊天记录。
- 下载过的附件默认不打包，避免备份巨大和无意复制公司文件；用户可以显式选择“包含附件”，并看到预计大小。
- 缓存、日志、临时文件、程序本体和插件永不进入备份。
- 包内每个条目记录相对路径、大小和 SHA-256；导入只接受允许的文件名，拒绝绝对路径和 `..`，防止路径穿越。
- 导入前自动创建当前工作区恢复点，完成后重启影聊。
- 工作区只在用户选定的本地路径读写，不上传到网站或 GitHub。

这比“绑定电脑 IP”更可靠：IP 会因 DHCP、网卡和办公地点变化，而工作区可以稳定迁移身份和历史。

## 7. 设置重组

普通设置只保留四组：

- 个人资料：名字、头像、状态。
- 消息与通知：声音、托盘、回车发送、聊天记录保留。
- 文件：下载位置、同名文件处理、传输确认。
- 隐私与更新：局域网加密状态、版本检查、导出或导入工作区。

端口、广播、组播、协议、压缩、代理、日志等进入“高级设置”，并提供“恢复安全默认值”。高级设置每项都要解释修改后果。

## 8. 网络、更新与安全

- 聊天和文件只建立局域网点对点连接。
- 不内置云存储、HTTP 文件上传、公网中继、代理转发或遥测。
- 系统代理不用于聊天连接。
- 插件和任意外部程序启动默认禁用；官方构建不捆绑第三方插件。
- 默认要求加密连接，不接受明文降级。
- 版本检查是唯一可选公网请求：固定 HTTPS 地址、最多每 7 天一次、只请求静态清单，请求内容不含设备 ID、用户名、联系人或使用数据；托管网站仍会像普通网页请求一样看到出口 IP。
- 客户端只提示新版本，不强制更新、不静默下载安装。
- 发布清单包含版本、下载地址、SHA-256 和签名；客户端验证后才展示下载入口。
- 无网络或请求失败时静默继续使用，不影响局域网聊天。

## 9. GitHub 与工具站架构

采用两个仓库，而不是把应用源码塞进个人站点仓库：

### `shadowyli/shadow-chat`

- 影聊源代码、许可证、构建说明和安全说明。
- GitHub Releases 存放安装包、便携包、校验值和版本清单。
- Issue、版本历史和贡献记录都归属于产品本身。
- BeeBEEP 是 GPLv3 项目，影聊作为派生版本继续以 GPLv3 分发，并保留原作者版权和第三方许可。

### `shadowyli/shadowyli.github.io`

- 作为中文工具站和个人职业作品入口。
- 影聊拥有独立产品页，但下载按钮直接指向 `shadow-chat` 的 Release 资产。
- 页面通过 GitHub Releases API 汇总安装包 `download_count`，不额外埋点、不记录下载者身份。
- 产品页展示版本、文件大小、SHA-256、更新日期、系统要求、三步使用说明和隐私承诺。

这样既能让员工“一眼找到下载”，又不会把网站发布和桌面应用开发混在同一个版本历史里。

## 10. 可用于简历的指标

只记录与产品改进有关且不识别个人的数据：

- GitHub Release 累计下载量和版本覆盖率。
- 从打开产品页到点击下载的转化率；若不愿引入网站分析，只展示下载量。
- 新用户从安装到首次发现同事的中位时间（线下可用测试记录，不在客户端遥测）。
- 多图任务完成步骤：原来“本地压缩 + 发送”，改为“拖入 + 一次确认”。
- 50 张图片发送产生的可见消息数量：50 条降为 1 组。
- 高频任务可用性测试成功率、平均用时和满意度。
- 每个版本修复的问题数、贡献者数、GitHub Star/Fork 和发布频率。

简历表达应基于真实数据，例如：“重构开源局域网通讯工具的核心聊天流程，将 50 张图片发送从 50 次可见消息降为 1 个图片组；建立独立发布仓库和中文下载站，累计获得 X 次安装包下载。”

## 11. 交付阶段

### P0：可用的聊天主路径

- 影聊品牌、现代三栏主界面、统一搜索和响应式布局。
- 嵌入式聊天、现代输入区、左右消息气泡。
- 多图一次确认和成组展示。
- 长消息展开。

### P1：普通员工能自行安装和迁移

- 三步首次使用。
- 简化设置。
- `.beebeep-workspace` 导出、导入和恢复点。
- 中文安装包、便携包和卸载流程。

### P2：可信发布

- 安全默认值收紧、版本清单校验、联网行为说明。
- 独立 GitHub 仓库、自动构建、Release 和校验值。
- 工具站影聊产品页、下载计数和安装说明。

### P3：质量与维护

- 两台隔离虚拟机互传消息、图片和文件的回归测试。
- 32 位 Windows 兼容性、升级覆盖安装、备份恢复和无网启动测试。
- 安全审查、依赖许可清单和公开安全报告入口。

## 12. 完成标准

- 新人无需指导即可在 5 分钟内完成安装、设置名字并找到同事。
- 2 至 50 张图片只需一次发送确认，并在聊天中作为一个图片组呈现。
- 常用入口在主界面可见，低频设置不干扰聊天。
- 断网时所有局域网功能正常；关闭更新检查后没有公网请求。
- 工作区可以导出到单文件并在另一台电脑恢复，导入失败不会破坏原数据。
- 安装包、源码、许可证、校验值和下载入口均可从中文产品页获得。
