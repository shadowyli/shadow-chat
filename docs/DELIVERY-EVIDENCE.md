## Runtime tests and remaining checks

- `tests/group_loopback_test.cpp` runs two real Core processes with independent on-disk profiles and multiple fresh-process phases. The folder phase instantiates production GuiMain and exercises its actual automatic downloadFolder slot, including a 503-file project sent twice, a zero-byte file and empty descendant directories. It verifies every received part file's bytes in both destination roots. This functional stress test configures 12 simultaneous downloads; the product default is 3, so the timings are not a default-setting speed benchmark. Results are recorded in `test/group-loopback.log`.
- `--images-only` sends two real PNG files in one batch, checks received bytes and requires both incoming preview markers to carry the same UUID. Results are recorded in `test/group-images.log`.
- Production GUI run: seed 6.9 seconds, offline queue/restart 1.7 seconds, 1006 completed files in 71.9 seconds, rejoin/cancellation 6.1 seconds, transfer/dissolve 4.1 seconds; all phases PASS. An earlier production GUI run exposed quadratic history rebuilding on each file-transfer card; GuiChat now appends those cards incrementally. No UI repaint suppression is used by the default runtime test.
- `--invite-only`: A and B first create and persist a group; A exits. B then meets fresh-profile C, who never connected to A. B invites C without the owner online; C retains A as owner and all three memberships. B/C exchange messages and a byte-verified PSD. PASS (invitation phase 3.9 seconds), `test/group-invite.log`.

## Honest limits

- Tests on one machine do not validate office VLAN discovery, enterprise firewall policy, Windows 10 versus 11 installation, or performance on 20 separate workstations.
- A peer cannot impersonate an offline owner to relay owner-authorized renames/removals. The owner's durable control queue synchronizes these changes when the owner next connects; ordinary chat/material delivery remains available while the owner is offline. An independently authenticated owner-change relay is not implemented.
- Delivery counts mean receiver-confirmed transport/storage, not human read receipts.
- Final packaging audit separately identified the fresh-PC Visual C++ runtime dependency. The installer builder now bundles the official x86 CRT DLLs app-local and the installation verifier checks their hashes; installation ownership and results remain in the release/packaging evidence, not these network tests.
